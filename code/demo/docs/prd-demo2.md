# 시연 ② PRD — 정책 한 줄만 바꿔보기

> 5주차 발표(2026-05-13) 시연 4건 중 두 번째.
> 청중이 "임계값(정책)이 데이터로 외부화되어 있으면 코드 0줄 수정으로 결과가 바뀐다"를
> 토글 한 번과 슬라이더 한 손가락으로 체득하게 한다.
>
> **버전**: v0.1 (2026-05-12)
> **선행**: 시연 ①에서 5건 segment의 `s-priority` attribute가 그래프에 적재되어 있어야 함

---

## 1. 목적 (왜 만드는가)

시연 ①은 "어떻게 위험도를 계산하는가"를 보여줬다. 시연 ②는 그 위에서 **"임계값만 바꾸면 결과가 어떻게 달라지는가"**를 한 화면에서 인터랙티브하게 보여준다.

청중이 인지해야 할 핵심 2가지:

1. **정책 = 데이터** — `threshold-set` 노드의 4개 값만 바꾸면 같은 점수가 다른 단계로 매핑됨. 코드 수정 0줄
2. **시뮬레이션이 자유** — v1/v2 사이를 즉시 오갈 수 있고, 슬라이더로 임의 정책도 즉석에서 시험 가능

---

## 2. 발표 스토리 (2분 시연)

> 시연 ①에서 5건이 그래프에 저장됐다는 걸 본 직후 이어서.
>
> 1. (진입) "이 5건이 시연 ①에서 저장된 거예요. 점수와 단계가 그래프에 있죠."
> 2. (v1 상태) "지금은 v1 임계값으로 매핑돼 있어요. 봉황면은 0.350인데 0.20~0.40 구간이라 감시 강화."
> 3. (v2 토글) "임계값을 v2로 바꿔봅니다. **클릭 한 번**. 봉황면이 검토 예비로 한 단계 올라갔어요. 코드는 1줄도 안 고쳤습니다."
> 4. (slider) "더 보수적으로 가고 싶으면 슬라이더로 직접 조정도 가능합니다. 0.30을 0.25로 내리면..." (슬라이더 드래그)
> 5. (마무리) "정책이 데이터로 외부화돼 있으니까, 시뮬레이션이 이렇게 자유로워집니다."

## 3. 입력 (사용자가 무엇을 조작하는가)

**한 화면에서 두 가지 조작:**

| 조작 | 효과 |
|---|---|
| **v1 / v2 / 사용자 임의** 토글 (3-way) | 임계값 4개를 그래프 또는 사용자 정의값으로 즉시 전환 |
| **4개 슬라이더** (low/mid_low/mid_high/high, 0.05~0.95) | 사용자 임의 임계값 조정. 자동으로 "사용자 임의" 토글로 전환 |

조작 시 5건 segment의 매핑 결과가 **즉석 갱신** (서버 호출 X, 클라 재매핑).

## 4. 단계 분해 (시연 ①보다 단순한 3단계)

시연 ①처럼 9단계 진행 비드 X. 한 화면에서 토글·슬라이더만 사용.

| 단계 | 사용자 액션 | 백엔드 호출 | 화면 동작 |
|:--:|---|---|---|
| 진입 | (자동) | `GET /api/demo2/segments-with-priority` + `POST /api/demo2/load-thresholds {version:v1}` | 5건 segment 표 + v1 임계값 컬러바 + v1 매핑 결과 |
| 1 | "v2" 토글 | `POST /api/demo2/load-thresholds {version:v2}` | 컬러바 + 매핑 결과 갱신. 격상된 segment에 ↑ 마커 |
| 2 | "v1" 토글 | (캐시) | v1 상태로 복귀 |
| 3 | 슬라이더 조작 | (서버 호출 X, 클라 재매핑) | 토글이 "사용자 임의"로 자동 전환. 매핑 결과 즉석 갱신 |

## 6. API 명세 (3개)

### 6.1 GET `/api/demo2/segments-with-priority`

시연 ①에서 적재된 5건의 `s-priority` (override 적용 전 base 점수).
이 시연은 **base-state 매핑만** 다루므로 `state-override-reason` 등은 무관.

```json
{
  "segments": [
    { "id": "EMD_무안_운남면",   "label": "무안 운남면",   "s_priority": 0.2945 },
    { "id": "EMD_나주_봉황면",   "label": "나주 봉황면",   "s_priority": 0.3499 },
    { "id": "EMD_장흥_유치면",   "label": "장흥 유치면",   "s_priority": 0.4537 },
    { "id": "EMD_광주_북구_001","label": "광주 북구 001", "s_priority": 0.4945 },
    { "id": "EMD_여수_상암동",   "label": "여수 상암동",   "s_priority": 0.5345 }
  ],
  "missing": []
}
```

**`missing`**: `s-priority` attribute가 없는 segment id 목록. 시연 ① 미실행 또는 reset 직후라면 5건 모두 missing. 클라는 안내 메시지 표시 + 매핑 결과를 빈 상태로.

### 6.2 POST `/api/demo2/load-thresholds`

바디: `{ "version": "v1" }` 또는 `{ "version": "v2" }`.

```json
{
  "version": "v1",
  "thresholds": { "low": 0.20, "mid_low": 0.40, "mid_high": 0.60, "high": 0.80 },
  "state_labels": [ /* 시연 ①과 동일 5개 */ ],
  "source": "graph://threshold-set[config-version=v1]",
  "available_versions": ["v1", "v2"]
}
```

v2 임계값이 그래프에 적재되지 않은 환경이면 503 + `hint_for_presenter: "test_param_externalization.py를 한 번 실행해 v2를 적재해주세요"`.

### 6.3 POST `/api/demo2/state-of`

(선택. 클라이언트가 직접 매핑해도 되지만, "사실은 같은 graph_inference 함수가 매핑한다"는 추적성을 위해 서버 측 매핑 API도 제공.)

바디: `{ "s_priority": 0.350, "thresholds": {...} }`

```json
{ "base_state": "EnhancedMonitoring", "band_index": 1 }
```

슬라이더 드래그 중에는 **클라이언트가 직접 매핑** (네트워크 부하·반응성). 토글 변경 시에만 6.2로 임계값 새로 받고, 매핑은 클라가.

### 공통 에러 응답
시연 ①과 동일 (`TYPEDB_UNAVAILABLE` 등).

## 7. 백엔드 구현 메모

### 7.1 재사용 함수 (graph_inference.py)
다음만 import. **신규 함수 추가 없음**:
- `load_thresholds(driver, metric, version)` — 6.2에서 호출
- `s_priority_to_state(sp, thresholds)` — 6.3 및 클라 미러 (클라 측 JS로 동일 로직 재구현)
- `make_driver`

### 7.2 segment의 s-priority 조회
시연 ①의 verify 쿼리와 유사하지만 **6 attribute 모두가 아니라 s-priority만 필요**. 매치 실패한 segment는 `missing` 목록에 추가.

### 7.3 클라이언트 측 매핑 미러
JS에 `s_priority_to_state(sp, thresholds)` 동일 로직 함수 1개. 슬라이더 onInput 시 즉시 5건 결과 재렌더. 100ms 안에 응답해야 인터랙션 자연스러움.

## 8. 비범위

- **override(safety/alert 격상) 적용** — 시연 ①에서 다뤘으므로 ②에서는 base-state만 비교. 시연 ②의 메시지는 "임계값만 바꿨을 때 매핑이 어떻게 바뀌는가"에 집중
- 슬라이더 값을 그래프에 INSERT(v3 임시 노드) — 발표 후 그래프 오염 위험. 클라이언트 즉석 재계산만
- 새로고침 시 슬라이더 값 보존 (Local Storage) — 비범위
- 모바일

## 9. 수용 기준

1. 시연 ①을 먼저 돌린 상태에서 `/demo2` 접속 시 5건 모두 `s_priority`가 표에 표시됨
2. 시연 ① 미실행 / reset 직후 접속 시 **명확한 안내 메시지** + 5건 빈 상태 ("시연 ①을 먼저 실행해주세요" 카드)
3. v1 ↔ v2 토글 1초 이내 반응
4. 슬라이더 onInput 시 100ms 이내 결과 재렌더 (네트워크 호출 없음)
5. v2 토글 시 **나주 봉황면**(0.350)·**여수 상암동**(0.534) 두 건이 격상되며 ↑ 마커 표시 — 발표 핵심 시각 효과
6. 책임님 라이브 시연 1회 통과
7. v2 임계값이 그래프에 없을 때 명확한 에러 + `hint_for_presenter`

## 11. 셀프 검증 (시연 ① 일반 교훈 반영)

시연 ① PRD 검증 보고서에서 도출된 4가지 일반 교훈을 본 PRD에 미리 적용한 결과:

1. **모든 숫자 예시는 실제 코드로 1회 검증** — 6.1 응답의 `s_priority` 5건은 본 PRD 작성 시점에 `test_param_externalization.py` 출력값(`0.295/0.350/0.454/0.495/0.534`)을 그대로 인용. 시연 ① UI로 새로 write-back한 후에는 약간 달라질 수 있음(예: 0.534 vs 0.5345). 4자리 정밀도면 같음.
2. **"무수정 재사용" 표현 신중** — 7.1에 명시. 신규 함수 추가 없음을 단언. graph_inference.py 무수정 가능.
3. **단일 진실 원천 명시** — segment 카탈로그는 `demo/api/segments_catalog.py`(시연 ① SSoT). 본 시연은 segment id만 사용하고 attribute는 그래프에서 조회.
4. **실패 시 발표자 동선** — 9.2(시연 ① 미실행), 9.7(v2 미적재) 두 시나리오 모두 안내 메시지로 흐름 보호.

추가 검증:
- 시연 ②가 시연 ①의 **base-state**만 다루고 override 결과는 무관하므로, 시연 ①에서 적재된 `base-state` attribute를 보여줄지 여부는 결정 필요. **결정: 본 시연은 매핑 비교가 목적이므로 base-state attribute는 표시 안 함. s_priority만 사용해 클라 측에서 새로 매핑.** 시연 ①과의 일관성보다 시연 ②의 단순함이 우선.
