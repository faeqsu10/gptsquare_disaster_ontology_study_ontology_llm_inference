# 시연 ③ PRD — 자연어로 그래프에 묻기

> 5주차 발표(2026-05-13) 시연 4건 중 세 번째.
> 청중이 "AI가 그래프 쿼리 언어를 직접 생성한다 + 실패 시 스스로 고친다 + 데이터 없으면 답을 만들지 않는다"를 자연어 질의 하나로 체득한다.
>
> **버전**: v0.1 (2026-05-12)
> **선행**: 시연 ①에서 5건 segment 적재 + 시연 ② threshold-set v1·v2 있는 상태 권장

---

## 1. 목적 (왜 만드는가)

기존 `chat.py`는 콘솔에서만 동작하고 자가 수정 흐름이 단일 print로 흘러간다. 본 시연은 그 흐름을 **4단계 카드로 펼쳐서** 청중이 "AI가 어떤 쿼리를 만들었고, 그게 실패했고, 어떻게 고쳤는지"를 직접 본다.

청중이 인지해야 할 핵심 3가지:

1. **AI가 그래프 쿼리를 직접 만든다** — Function Calling이 아니라 TypeQL을 한 번에 생성
2. **자가 수정 (Self-correcting)** — 실패한 쿼리의 에러 메시지를 다시 AI에게 보내면 스스로 고침
3. **환각 방지** — 데이터가 없으면 "없다"고 말함. LLM이 사실을 지어내지 않음

## 2. 발표 스토리 (5분)

> 3가지 질의로 3개 메시지를 보여준다.
>
> **질의 1: "EMD_여수_상암동 위험도 알려줘"** (단순 — 메시지 ①)
> - 단계 1 (TypeQL 생성): "AI가 자연어를 보고 이런 TypeQL을 만들었습니다." 코드 박스 표시
> - 단계 2 (실행): "그래프에서 1건 조회 성공"
> - 단계 3 (답변): "여수 상암동은 우선 예비 상태입니다. 경보 격상 사유 때문."
>
> **질의 2: "MOCK 상태인 source 모두"** (advisory — 메시지 ① + advisory)
> - 단계 1·2: 정상 진행
> - 단계 3 (답변): "6건 조회됐습니다. ⚠️ 일부 데이터는 추정값(MOCK)입니다." advisory 자동 부착
>
> **질의 3: "1990년 1월 광주 동구 위험도?"** (환각 방지 — 메시지 ③)
> - 단계 1: TypeQL 생성됨
> - 단계 2: 0건 조회 — 자가 수정 트리거
> - 단계 1·2 (시도 2): 다른 TypeQL 생성·실행 — 여전히 0건
> - 단계 3 (답변): "해당 시점의 데이터가 없습니다." — 추측 X
>
> 마무리: "이게 PoC가 다루는 환각 방지의 실체입니다."

## 4. 단계 분해 (4단계, 자동 펼침)

사용자 인터랙션은 **"물어보기" 버튼 클릭 한 번만**. 이후 4단계 카드가 백엔드 응답에 맞춰 순차로 펼쳐진다 (각 카드 약 600ms 간격으로 등장).

| 단계 | 내용 | 화면 표시 |
|:--:|---|---|
| 1 | 질문 echo | 사용자 입력을 카드로 다시 표시 |
| 2 | TypeQL 생성 + 실행 (시도 1) | 코드 박스 + 결과(JSON 또는 에러) + 라벨(성공/0건/실패) |
| 2b | 자가 수정 (시도 2~3) | (시도 1이 실패한 경우만) 새 코드 박스 + 새 결과. **"자가 수정"** 강조 라벨 |
| 3 | Fallback (선택) | (Gemini 실패한 경우만) golden TypeQL로 대체. **"예비 답안"** 라벨 |
| 4 | 자연어 답변 + advisory | 최종 답변 박스 + MOCK·격상 사유 advisory 칩 |

각 카드는 펼쳐지면서 색깔 라벨이 붙는다:
- 시도 1 성공 → 녹색 ✓
- 시도 1 실패·시도 2 성공 → 주황 🔁 자가 수정
- 모두 실패·fallback 성공 → 파랑 🔄 예비 답안
- 완전 실패 (환각 방지) → 회색 — 답을 만들지 않음

## 6. API 명세 (1개)

### 6.1 POST `/api/demo3/ask`

바디:
```json
{ "query": "EMD_여수_상암동 위험도 알려줘", "case_id": "1-1" }
```

- `query` (필수): 자연어 질문 (1~300자)
- `case_id` (선택): 평가셋 case id — 모두 실패 시 fallback TypeQL 사용

응답:
```json
{
  "question": "EMD_여수_상암동 위험도 알려줘",
  "trail": [
    {
      "attempt": 1,
      "typeql": "match $s isa segment, has segment-id \"EMD_여수_상암동\", has state $st, has state-override-reason $r; select $st, $r;",
      "ok": true,
      "result_count": 1,
      "result": [{"st": "PriorityPreWatering", "r": "alert_경보_priority_6"}],
      "error": null
    }
  ],
  "fallback_used": false,
  "final_status": "success",
  "answer": "여수 상암동은 현재 PriorityPreWatering(우선 예비) 상태입니다. 기상특보 경보 발효로 인해 단계가 격상되었습니다.",
  "advisory": []
}
```

`advisory`: `["MOCK 데이터 포함", "경보 격상"]` 같은 짧은 칩 라벨. 자연어 답변에 이미 포함된 내용을 별도 시각화.

`trail`은 실패 시 길어짐 (최대 3시도 + fallback). 응답 시간은 시도당 ~1.5초, 최대 ~5초.

### 공통 에러 응답

```json
{ "ok": false, "error_code": "GEMINI_UNAVAILABLE",
  "message": "Gemini API 호출 실패: ...",
  "hint_for_presenter": ".env의 GEMINI_API_KEY를 확인해주세요." }
```

## 7. 백엔드 구현 메모

### 7.1 text_to_typeql.py에 추가

기존 `query_with_self_correction`은 마지막 시도만 반환하므로 trail 시각화 어렵다. **새 함수** `query_with_trail` 추가 — 기존 함수와 동일 로직이되 모든 시도의 trail을 dict로 반환. 기존 함수는 무수정.

### 7.2 demo3.py 라우터

```
- text_to_typeql.query_with_trail 호출
- 성공/fallback 시 chat.py의 ANSWER_SYSTEM 프롬프트로 Gemini 답변 생성
- advisory 추출: 결과 JSON에서 MOCK / override reason을 추출해 짧은 칩 라벨 생성
- 응답 dict 반환
```

### 7.3 advisory 추출 규칙

| 조건 | 칩 라벨 |
|---|---|
| 결과에 `availability-status == "MOCK"` 있음 | `⚠️ MOCK 데이터 포함` |
| 결과에 `state-override-reason == "alert_경보_priority_6"` | `↑ 경보 격상` |
| 결과에 `state-override-reason == "hazard_gate_priority_1"` | `⛔ 안전 게이트` |
| 결과 0건 + fallback X | (advisory 없음, 답변에서 "없습니다" 처리) |

## 9. 수용 기준

1. 3가지 질의 모두 응답 시간 5초 이내 (단순 ~2초, 자가 수정 ~4초)
2. 질의 1 (여수): 1회 성공 → 자연어 답변에 "PriorityPreWatering" 또는 "우선 예비" 포함
3. 질의 2 (MOCK): 6건 결과 + advisory `⚠️ MOCK 데이터 포함` 칩 표시
4. 질의 3 (1990 광주 동구): 답변에 "없습니다" 또는 "데이터가 존재하지 않" 같은 표현 — 추측 X
5. Gemini가 한 번에 실패한 경우 시도 2가 자동 추가 + "🔁 자가 수정" 라벨
6. 4단계 카드가 약 600ms 간격으로 부드럽게 펼쳐짐
7. 책임님 라이브 시연 1회 통과

## 11. 셀프 검증 (시연 ①·② 일반 교훈 반영)

1. **숫자 예시는 실제 코드로 검증** — 본 시연은 Gemini가 매번 다른 TypeQL을 생성하므로 정확한 코드 예시 X. 발표 시 표시되는 typeql은 그 회차의 실제 응답이라 PRD 예시와 다를 수 있음 — 청중에게 미리 안내
2. **무수정 재사용 표현** — 7.1에 `query_with_trail` 신규 함수 추가 명시. text_to_typeql.py·chat.py는 무수정
3. **단일 진실 원천** — schema/임계값/segment는 그래프 + segments_catalog로 일관
4. **실패 시 발표자 동선** — Gemini API 실패는 503 + hint 표시. 환각 방지 케이스는 "실패가 아니라 의도된 답"이라 발표자가 멘트로 강조
